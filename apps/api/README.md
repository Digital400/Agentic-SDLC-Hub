# API (FastAPI)

See the root [README.md](../../README.md) for full run instructions. Quick start:

```bash
cd apps/api
python -m venv .venv
.venv\Scripts\activate      # Windows
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000
```

Health check: `GET http://localhost:8000/health`

## Database

Models live in [app/models/](app/models/) — one file per concept (user,
project, workflow, artifact, review, agent, audit). See the module docstring
in [app/models/base.py](app/models/base.py) for why the model files don't
import each other directly.

A project's `WorkflowNode`/`WorkflowEdge` rows aren't hand-authored — they're
generated once, when the project is created, from a workflow template JSON
file (e.g. [workflows/sdlc-workflow.json](../../workflows/sdlc-workflow.json))
by [app/services/workflow_templates.py](app/services/workflow_templates.py).

Set `DATABASE_URL` (see `.env.example`) to point at a running PostgreSQL
instance, then:

```bash
# Apply all migrations (creates the schema)
alembic upgrade head

# Load one realistic sample project, walked through its first stage
python -m app.db.seed
```

`python -m app.db.seed` is safe to re-run — it skips seeding if the sample
project already exists.

### Migrations

Standard Alembic workflow, run from `apps/api`:

```bash
alembic revision --autogenerate -m "describe the change"   # after editing models
alembic upgrade head                                        # apply
alembic downgrade -1                                         # roll back one step
```

Always read an autogenerated migration before committing it — in particular,
circular foreign keys (like `Artifact.current_version_id` <->
`ArtifactVersion.artifact_id`) need the deferred-FK pattern already used in
the initial migration (`op.batch_alter_table(...).create_foreign_key(...)`
after both tables exist), which autogenerate does not produce correctly on
its own.
