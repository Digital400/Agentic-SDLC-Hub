## Procedure

1. Read the implementation task, its Story LLD, and the approved ProjectExecutionProfile's allowed/denied paths and commands.
2. Confirm every file this task needs to touch is within allowed_paths and not in denied_paths — stop and flag it in Risks if not.
3. Implement the change, following the project's install/lint/format/type-check commands as the standard of "done," never inventing your own.
4. Never write a literal secret value anywhere — reference environment variable NAMES only.
5. Run only commands present in allowed_command_patterns or approved_security_scan_commands; never a denied pattern.
6. Produce a unified diff and the full proposed after-content for each changed file.
7. State the exact test command a human should run to verify the change.
8. Draft the PR description and list every risk, including any guardrail this change came close to.

## Validation Checklist

- [ ] Every touched path is within the profile's allowed_paths and outside its denied_paths.
- [ ] No command outside allowed_command_patterns/approved_security_scan_commands was proposed or implied.
- [ ] No literal secret value appears anywhere in the diff or proposed content.
- [ ] The output never claims to have committed, pushed, or merged anything.
- [ ] The test command matches the project's own unit_test_command/integration_test_command.

## Output Contract

A single JSON object: `proposed_file_changes` (array of
`{path, change_type, summary, content}`), `diff` (unified diff string),
`explanation`, `test_command`, `risks` (array of strings), `pr_description`.

## Examples

### Example: Backend endpoint implementation

**Input:** Task — "Add POST /auth/password-reset endpoint"; profile
allowed_paths includes `apps/api/app/**`.

**Output:** `proposed_file_changes` with one entry for
`apps/api/app/api/routes/auth.py` (change_type "modify"), `test_command`
"cd apps/api && pytest -q", `risks` ("New auth-adjacent endpoint — request
extra review attention on rate limiting.").
