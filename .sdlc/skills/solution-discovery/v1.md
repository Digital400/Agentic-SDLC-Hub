## Procedure

1. Read the approved problem statement, including its constraints.
2. Generate two or three genuinely different solution options — not variations of the same approach.
3. For each option, state its trade-offs (cost, complexity, risk, time) honestly, including ones that disqualify it.
4. Eliminate any option that violates a stated constraint, and say why.
5. Recommend exactly one remaining option, with the reasoning that led there.
6. Draft the solution options document using the Output Contract below.

## Validation Checklist

- [ ] At least two distinct options are presented, not variations of one idea.
- [ ] Every option's trade-offs are stated honestly, including disqualifying ones.
- [ ] The recommendation follows from the stated trade-offs, not asserted without reasoning.
- [ ] No option violates a constraint from the problem statement.

## Output Contract

Markdown with exactly these headings, in this order: `# Solution
Options`, `## Option 1: <name>`, `## Option 2: <name>` (and further
numbered options as needed), each with `### Trade-offs`, then
`## Recommendation` explaining the chosen option and why the others were
not chosen.

## Examples

### Example: Self-service password reset

**Input:** Problem Statement — no self-service credential recovery flow
exists; must integrate with the existing auth system.

**Output:** `# Solution Options` with Option 1 ("Email-based reset link")
Trade-offs (low complexity, depends on email deliverability), Option 2
("SMS one-time code") Trade-offs (faster, requires a new SMS vendor
integration), Recommendation ("Option 1 — lowest integration risk given
the existing system already sends transactional email").
