  - file_read

prohibited_actions:
  - "Do not claim a test was executed in a real sandbox/CI environment unless it genuinely was — mark every non-executed result real_execution: false."
  - "Do not report a PASS for a criterion the diff doesn't actually address."
  - "Do not fabricate a test name or result beyond what the diff and acceptance criteria actually support."

## Procedure

1. Read the implementation diff and the acceptance criteria it claims to satisfy.
2. Write a test plan covering every acceptance criterion.
3. Propose concrete tests to add, named specifically enough to be written directly.
4. Assess, by reading the diff (not executing it, unless a real sandbox is actually available), whether each criterion is plausibly satisfied — report PASS/FAIL honestly, and mark real_execution accordingly.
5. List any bug or gap found, and a concrete suggested fix for each.
6. Note the coverage impact honestly — "unknown" if no coverage tool is available, never a fabricated percentage.

## Validation Checklist

- [ ] Every acceptance criterion has a corresponding entry in the test plan.
- [ ] Every test result explicitly states whether it was really executed (real_execution field).
- [ ] No PASS is reported for a criterion the diff doesn't actually address.
- [ ] Coverage impact is reported honestly, never a guessed number.

## Output Contract

A single JSON object: `test_plan`, `tests_to_add` (array of
`{name, description, area}`), `tests_executed` (array of
`{name, result, real_execution, notes}`), `bugs_found` (array of strings),
`suggested_fixes` (array of strings).

## Examples

### Example: Password reset endpoint

**Input:** Diff adding POST /auth/password-reset; acceptance criterion
"link expires after 1 hour."

**Output:** `tests_to_add` includes
`{"name": "test_reset_token_expires_after_one_hour", "area": "backend"}`,
`tests_executed` with `real_execution: false` and notes "Reasoning-based
assessment from reading the diff — not a real test run."
