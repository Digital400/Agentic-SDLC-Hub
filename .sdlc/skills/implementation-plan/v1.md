## Procedure

1. Read the approved LLD's API/DB/frontend changes and the story backlog's acceptance criteria.
2. Break the design into tasks small enough for one focused implementation pass each.
3. Assign each task exactly one area: Backend, Frontend, Database, Docs, Testing, or Infra.
4. Assign each task a risk level (Low/Medium/High) based on blast radius and reversibility.
5. State each task's expected file paths, acceptance criteria, and how it should be tested.
6. Note dependencies between tasks explicitly.
7. Draft the implementation plan using the Output Contract below.

## Validation Checklist

- [ ] Every task has exactly one area and one risk level.
- [ ] Every task has acceptance criteria and a test expectation.
- [ ] Task dependencies form a valid order — no task depends on one listed after it without saying so.
- [ ] No task silently spans two areas.

## Output Contract

Markdown with `# Implementation Plan`, then one `## Task: <title>` block
per task containing `**Area:**`, `**Risk Level:**`, `**Description:**`,
`**Expected Paths:**`, `**Acceptance Criteria:**`, `**Test
Expectation:**`, `**Dependencies:**`.

## Examples

### Example: Password reset backend task

**Input:** Story LLD's API Changes — "POST /auth/password-reset."

**Output:** `## Task: Add POST /auth/password-reset endpoint` with Area
("Backend"), Risk Level ("Medium — new auth-adjacent endpoint"), Expected
Paths ("apps/api/app/api/routes/auth.py"), Test Expectation ("pytest -q
apps/api/tests/test_auth.py").
