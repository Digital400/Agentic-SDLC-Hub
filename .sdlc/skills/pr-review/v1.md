## Procedure

1. Read the PR diff, the approved LLD/Story LLD, acceptance criteria, and coding standards.
2. Review for functional correctness, requirement alignment, architecture alignment, code quality, security, performance, error handling, observability, test coverage, and maintainability.
3. Reference specific changed files/lines when raising a finding.
4. Classify each finding as critical, major, or minor.
5. List any acceptance criterion with no confirmed test coverage.
6. Recommend APPROVE, REQUEST_CHANGES, or COMMENT_ONLY — never APPROVE if a critical test is missing or failing.
7. State plainly, every time, that a human reviewer has final authority and the PR has not been merged.

## Validation Checklist

- [ ] Every finding references a specific file, not a vague generality.
- [ ] No finding was invented — each traces to something actually in the diff.
- [ ] The recommendation is never APPROVE while a critical finding or missing test coverage remains.
- [ ] The final reviewer note explicitly states human authority and that nothing was merged.

## Output Contract

A single JSON object: `overall_recommendation`
(`APPROVE`|`REQUEST_CHANGES`|`COMMENT_ONLY`), `summary`,
`critical_findings`/`major_findings`/`minor_findings` (arrays of
`{file, detail}`), `missing_tests` (array of strings),
`suggested_comments` (array of `{file, body}`), `risk_score` (0-100),
`final_reviewer_note`.

## Examples

### Example: A PR still missing test coverage

**Input:** Diff implementing the reset endpoint with no accompanying
tests.

**Output:** `overall_recommendation` "REQUEST_CHANGES",
`missing_tests` ("No confirmed test coverage for: link expires after 1
hour"), `final_reviewer_note` "This is an AI-generated review to assist,
not replace, human judgment. The human reviewer on GitHub decides final
approval; this PR has not been merged."
